能力测试

每个按钮点一下,结果打在最下面的日志里。真机上才有意义。

现在是在普通浏览器里,所有按钮都禁用了。 app-shell.js 只在 app 里初始化。
看日志里的 code。 unsupported = 这个能力没编进 app; denied = 用户拒了权限; nobridge = 跳到站外了; failed = 插件自己报的错(原始错误会跟在下一行)。

生物识别

verify 成功只证明「手机的主人在场」,不等于登录。 用户按取消也会走 catch —— 那不是故障。

保存到相册

两个按钮走的是不同的输入:一个给网址,一个给 data: base64。 Android 会按 CONFIG.albumName(现在是 testing)找/建相册, iOS 不指定相册、走只写权限。存完去系统相册里看一眼有没有真的出现。

本地通知

不是推送 —— 这是手机自己排的,不经服务器。 「10 秒后」那个点完把 app 切后台,通知才显眼。 我们刻意撤掉了精确闹钟权限(SCHEDULE_EXACT_ALARM,带着它过不了 Play 审核), 所以系统可能晚几秒到几分钟才弹 —— 那是预期行为,不是 bug。

剪贴板

只有写,刻意没有读。点完去别的输入框长按粘贴验证。

设备 ID

卸载重装会变,不能当账号用。

评分弹窗

什么都没弹是正常的 —— 两端系统都有频率限制,而且 API 不告诉你弹没弹。 debug 包基本上弹不出来。日志里出现「已调用」就算过。

触觉反馈

这一项要用手感,不看日志。七个按钮震感应该不一样。 iOS 模拟器完全没感觉,必须真机; 设备没马达、系统关了振动、静音模式都会让它什么都不发生 —— 那不是错误。

自动重连

网络恢复后壳会自动刷一次,但有没填完的东西时不刷。 下面这个输入框就是用来验「不刷」那一半的。

测法 A(应该自动刷):别碰输入框,开飞行模式 → 关掉。页面应该自己刷新。
测法 B(应该不刷):先在下面打几个字,再开关飞行模式。应该只弹提示、不刷新。

扫码(应该是关着的)
